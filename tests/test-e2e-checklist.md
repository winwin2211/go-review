## Notes / false positives seen

No false positives in either run. All five specialists returned empty on `clean`.

Two observations worth keeping:

1. The first `clean` run (before commit edba916) returned APPROVE WITH COMMENTS
   with one MAJOR: the fixture's own `TestPlaceOrder` asserted neither that
   `Save` is called once nor that the wrapped error mentions the order id, both
   of which its spec requires. That was a correct finding against the fixture,
   not a false positive, so the fixture's test was fixed to satisfy its spec.
   The re-run returns APPROVE.
2. That same run exposed a real defect in `assert-clean.sh`: when the repo path
   was briefly unreachable, `git status --porcelain` printed nothing and compared
   equal to the empty baseline, so the script reported "verified" for a repo it
   never checked. It now fails closed on a non-git `--repo` or missing baseline
   files. Both are covered by tests.

3. `govulncheck` was not installed on the test machine, so the tools line reported
`vuln unavailable (missing)` in both runs and the report named the install
command. That is the designed behavior for a missing optional tool.
